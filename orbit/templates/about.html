About Orbit

Run a model on hardware a person controls, as easily as opening a browser tab.

Open models are free. The hardware is not, and most of it sits idle. Orbit is the broker between the two. The direction is simple: any open model, on any computer, with nobody in the middle keeping the data.

User
Types a model name or pastes a Hugging Face link. Sees which machines fit it. Adds hardware time, shown in dollars and minutes. Starts. Stops. Sees exactly what was used.
Host
Lists a machine and sets a price per hour. Runs the host program. It dials out, so a home router needs no changes. Paid for every minute of use. Nothing for listing.
Orbit
Matches, counts minutes, moves money. Takes {{ cut }}% of each session. It never runs a model. It relays the conversation as sealed envelopes and deletes them when the session ends.

The page says "sealed from Orbit". It does not say "private", because the host can read everything. To protect the conversation from the host too, the model must run inside enclave hardware that the browser can check. That is designed and not built. The full map is in docs/PRIVACY.md.

The rules

What Orbit is built on.

  1. A broker, not a middleman. Orbit forwards sealed envelopes it cannot open.
  2. One user, one machine. Exclusive for the session. No sharing, no bidding.
  3. Hosts are paid for use, never for listing.
  4. No promises, no claims. Every number shown is measured or set by a host. Unknown shows as unknown.
  5. Money is double-entry. Every movement is rows that sum to zero. /health reports if the books stop balancing.
  6. No datacenter. One ordinary machine runs Orbit. Hosts do the heavy work.
Works today

Version 0.1.

  • Model fit from the Hugging Face name or link, with "unknown" when the name does not say.
  • Exclusive sessions, charged by the minute from the moment the host says the model is ready.
  • Sessions end on their own when the time runs out or the host stops answering. The charge covers only the time that was reachable.
  • Double-entry ledger. The host is paid and Orbit's share is taken when the session ends.
  • Host program: heartbeat, runs the model with llama.cpp, relays the chat, stops the model at the end.
  • Chat sealed between the browser and the host's machine: ECDH P-256, HKDF, AES-256-GCM.
  • The full loop settled correctly on real hardware: one host, a Radeon RX 580 with 8 GB.
Not built yet

Next, in order.

  1. Verified hosts. The model runs in enclave hardware and the browser checks the attestation before it sends a word.
  2. The guide. One tip per session event. It never sees the chat.
  3. Host payouts. Money leaves Orbit to hosts, recorded in the ledger.
  4. Host program installs like an app on Windows, Mac and Linux.
  5. Streamed replies through the sealed relay.

Card payments are wired to Stripe and need keys. The build order is in docs/NEXT.md.

For a builder who joins

Read it, run it, check it.

Orbit is small on purpose: Python, FastAPI, SQLite, server-rendered pages, no build step. One file moves money. The tests cover the ledger, the session clock, recovery and the sealing, including an adversary suite.

What the sandbox is.

This address runs the real Orbit code in sandbox mode, so anyone can walk the loop without a card or a GPU. The booking, the minute clock, the ledger and the key exchange are the real code paths. These parts are not real:

  • The machines are simulated. No model runs. Replies are scripted and say so.
  • The money is test funds. No card is taken.
  • The simulated host runs on the same server as Orbit, so the sandbox shows how sealing works, not the privacy it gives with a real host.
  • You enter as a guest. No email or password is asked for or kept. Everything is wiped often.
